# Mihomo Desk 0.1.0 Windows 试用说明

## 启动

1. 完整解压 ZIP，不要只复制其中的 exe。
2. 双击 **MihomoDesk.exe**。需要 Windows x64 和 .NET Framework 4.8 或以上。
3. 托盘出现图标，默认浏览器自动打开管理页面。无需安装 Node，也不使用 WebView2。
4. 在「订阅管理」添加订阅地址，或导入 YAML 文件。
5. 在「YAML 覆写」「可视化规则」中编辑，先保存草稿，再校验、应用。
6. 在「节点与测速」选择真实内核节点，在「运行概览」切换规则／全局／直连模式。

关闭浏览器后，后台与代理继续运行。左键点击托盘可重新打开管理页；右键提供内核启动、停止、重启及退出入口。

默认本地代理端口：**127.0.0.1:17890**。系统代理默认关闭，需要时在页面或托盘中明确开启。开启会修改当前用户的系统代理；停止或正常退出时恢复此前设置。如果其他程序随后改动了这些设置，会保留新设置。

默认数据目录：`%LOCALAPPDATA%\MihomoDesk`。不会导入、修改或停止原有 Verge 数据与服务。端口冲突会报错，不接管现有进程。

## 首版已完成

- 独立 Windows 托盘、浏览器管理、本地认证 API。
- 订阅添加、编辑、删除、手动更新和切换。
- 全局及订阅 YAML 覆写；更新订阅后保留已保存的个人覆写和规则。
- 规则类型、匹配值、目标策略、启用状态、排序、前置／追加／整体替换；追加规则放在 MATCH 前。
- 真实内核节点选择、测速、模式及生命周期管理，近期日志和错误显示。
- 校验失败保留原运行配置；应用或保存失败时回退。

原始订阅 → 全局 YAML → 订阅 YAML → 可视化规则。代理组及其他数组**整体替换，不按名字合并**；DNS 子项和 hosts 遵循上游合并语义。

## 验证结果与边界

本机通过 6 项自动化测试，以及独立 Edge 的页面流程测试。验证了真实内核代理请求、节点与模式切换、订阅更新保留修改、无效配置回退、来源／认证检查、端口冲突不影响原监听、浏览器关闭后常驻、重复启动复用、重启后配置保留，以及托盘被强制结束后的子进程清理。

未对本机实际系统代理设置执行切换测试，避免影响当前使用。没有验证真实付费订阅、公司终端管控环境、provider／地理数据下载或上游 Tauri 完整客户端。不能保证解决公司电脑原有闪退。

首版不支持脚本覆写、自定义增强链、自动订阅更新、Verge 数据导入、自启和自动升级。TUN、额外监听、局域网开放、DNS 监听暂时关闭；本地文件 provider 暂不支持。订阅下载使用直连。程序未签名。

托盘被强制结束时，Windows Job 会清理本程序子进程，但系统代理恢复需要重新启动程序；正常退出会立即恢复。必要时手动恢复：

```powershell
.\MihomoDesk.exe --proxy-off
```

独立目录和端口试用：

```powershell
.\MihomoDesk.exe --data-dir "C:\temp\MihomoDesk-test" --mixed-port 27890 --controller-port 29090 --no-open
```

订阅和口令保存在本地文件中，请保护自己的 Windows 账户，不要分享管理页启动链接或 `instance.json`。

程序源码随包放在 `source/desk/`；详细构建说明见 README.md。保留 GPL-3.0-only 和 Clash Verge Rev 上游署名，第三方许可见 THIRD_PARTY.md。
